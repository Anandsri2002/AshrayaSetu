# AshrayaSetu
AashraySetu is a modern NGO donation and financial-assistance platform connecting people in need with donors. It features assistance requests, donation flows, request tracking, simulated payments, impact stories, transparency, and an admin dashboard. Built with React, Vite, and Tailwind CSS.


## Prototype Notice

AashraySetu is a UI/UX prototype created for demonstration and client review.

All beneficiary profiles, donation amounts, transaction IDs, bank information,
statistics and payment interactions shown in this repository are fictional/demo data.

Third-party assets and libraries are used under their respective licenses.



# AashraySetu – A Bridge to Hope

## 1. Project Overview

**AashraySetu** is a modern NGO donation and financial-assistance platform designed to connect people who need financial help with individuals who are willing to support them.

The platform provides a simple and transparent digital environment where:

- Needy individuals can submit financial assistance requests.
- Donors can browse verified/demo assistance cases.
- Donors can select the amount they want to contribute.
- Users can view detailed information about assistance requests.
- Donation payments can be simulated through a modern payment gateway interface.
- Users can track submitted assistance requests.
- The platform provides transparency and impact information.
- Administrators can view donation and assistance-related information through a dashboard.

### Tagline

**“A Bridge to Hope.”**

The name represents the purpose of the platform: creating a bridge between people who need help and people who want to provide help.

---

# 2. Main Objective

The primary objective of AashraySetu is to create a user-friendly digital platform for connecting donors and people seeking financial assistance.

Traditional donation systems can make it difficult for donors to understand where their money is going and for needy individuals to communicate their requirements.

AashraySetu addresses this problem by providing a structured platform where assistance requests can be presented with:

- Request ID
- Applicant name
- Location
- Assistance category
- Amount required
- Amount already raised
- Remaining amount
- Urgency level
- Supporter count
- Request description
- Progress information

The platform is designed to improve **accessibility, transparency, trust, and user experience**.

# 6. Demo Payment Gateway

AashraySetu contains a simulated payment gateway interface.

The interface demonstrates how a real payment system could look.

Available demo payment methods include:

### UPI

The user can select UPI as the payment method.

### Debit/Credit Card

A card payment interface is provided as part of the prototype.

### Net Banking

A net-banking option is also represented.

After selecting the payment method, the prototype can simulate a successful payment.

A simulated transaction ID and donation ID can then be displayed.

### Important

The current prototype does **not** process real payments.

A production implementation would require integration with a payment provider such as Razorpay, Cashfree, PayU, Stripe, or another appropriate payment gateway.

# 12. How It Works

The platform explains the complete process in simple steps.

### Step 1 – Raise a Request

A person requiring financial support submits an assistance request.

### Step 2 – Review & Verification

The NGO administration reviews the submitted information and supporting documents.

### Step 3 – Publish Assistance Case

After approval, the case can be made available to donors.

### Step 4 – Donors Contribute

Donors select a case and contribute an amount.

### Step 5 – Funding Progress

The amount raised is displayed against the required amount.

### Step 6 – Assistance

Once the required funding and verification requirements are fulfilled, assistance can be provided.

# 26. Security Considerations

The current version is a frontend prototype and therefore does not provide production-level security.

Before deploying the actual system, the following should be implemented:

### Authentication

Secure user authentication.

### Authorization

Different permissions for:

- Donors
- Applicants
- NGO employees
- Administrators

### Data Protection

Sensitive information such as bank details and identity documents must be securely stored.

### Payment Security

Payment information must be handled by a PCI-compliant payment provider.

### File Upload Security

Uploaded documents should be:

- Validated
- Virus scanned
- Size restricted
- Securely stored
- Access controlled

### API Security

Production APIs should implement:

- Authentication
- Authorization
- Rate limiting
- Input validation
- Logging
- Error handling

# 29. Payment Gateway Integration

For production, the simulated payment system should be replaced with a real payment gateway.

The workflow would be:

```text
Donor
  ↓
Select Assistance Case
  ↓
Select Donation Amount
  ↓
Payment Gateway
  ↓
Payment Processing
  ↓
Payment Verification
  ↓
Donation Recorded
  ↓
Receipt Generated
  ↓
Request Funding Updated
```

The application should never store raw card information.

---

# 30. Verification Workflow

One of the most important production features should be beneficiary verification.

A possible workflow:

```text
Request Submitted
       ↓
Initial Review
       ↓
Document Verification
       ↓
Phone Verification
       ↓
Field/NGO Verification
       ↓
Admin Approval
       ↓
Request Published
       ↓
Donation/Funding
       ↓
Assistance Delivered
       ↓
Completion Report
```

This would significantly improve trust and reduce fraudulent requests.
